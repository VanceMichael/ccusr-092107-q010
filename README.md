# 中小企业数字服务适配

描述中小企业转型需求、数字服务能力、补贴和验收证据。

## 领域资料

`contracts/` 下的 JSON Schema 约定资料格式，`fixtures/` 提供不含真实个人信息的虚构示例，`src/domain.js` 负责跨文档不变量校验与账本查询。后续业务服务可沿用其中的领域标识与版本约定。

| 资料 | 合约 / 样例 | 记录的业务事实 |
| --- | --- | --- |
| 基础领域说明 | `contracts/context.schema.json` · `fixtures/context.json` | 领域标识、版本与事实清单 |
| 企业画像 | `contracts/enterprise.schema.json` · `fixtures/enterprise.json` | 产线工序、**实测基线（每条指标挂证据）**、目标、停机窗口与预算约束、企业自有证据仓 |
| 行业均值 | `contracts/industry.schema.json` · `fixtures/industry.json` | `usage=comparison_only`，只能事后对比，不能充当基线或打分输入 |
| 产品披露 | `contracts/products.schema.json` · `fixtures/products.json` | 能力边界 `does/does_not`、硬性实施前提、停机需求、**带有效期的报价版本**、可验证案例 |
| 供需匹配 | `contracts/matching.schema.json` · `fixtures/matching.json` | 逐维度（工序/窗口/预算/前提/边界/案例）评级与理由；推荐项必须过硬性约束；预期效果引用企业基线且尽调阶段不构成承诺 |
| 签约后账本 | `contracts/engagement.schema.json` · `fixtures/engagement.json` | 多家并行尽调、补贴占用与释放、数据按集授权与退出撤销、阶段验收、失败退出、更换服务商；签约/部署/指标变化/持续使用分类型事件账本 |

样例以一个虚构的 32 人冲压件厂贯穿：自述瓶颈是换模工序（实测 118 分钟/次）、每周日仅 4 小时停机窗、首年预算 20 万。匹配结论推荐收窄边界的轻量换模看板，拒绝功能齐全但需 16 小时连续割接且超预算的全栈 MES；账本还记录了前一年与该 MES 签约后失败退出（撤授权、释放补贴、证据留存）、次年更换服务商并通过指标验收的完整过程。

### 关键不变量（由 `src/domain.js` 强制）

- 基线指标必须有实测来源与证据引用；目标只能引用本企业基线指标，行业均值标识无法通过校验
- 每个产品恰有一个 `active` 报价，被替代报价必须带 `valid_to`；必须披露硬性前提与 `does_not` 边界
- `recommend` 候选不得有 fail 维度，且生效报价首年费用与停机需求必须落入企业约束；`reject` 候选必须列出硬阻断项
- 失败退出：数据授权全部撤销、补贴零拨付释放、须有原因与数据删除证据
- 同一补贴同一时点不得被两个项目重复占用；账本累计拨付必须与占用记录一致
- 事件账本按时间追加；指标变化事件必须同时携带基线值；持续使用报告与登记证据均标记归企业留存
- 更换服务商保留的证据必须存在于企业自有证据仓

## 本地校验

```bash
npm test
```

测试既验证五份样例全部合法，也通过变异反面用例确认上述每条不变量都会被拦截。示例中的编号、金额、案例与哈希均为虚构值，不包含账号、凭据或真实主体信息。
