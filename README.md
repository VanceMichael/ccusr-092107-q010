# 中小企业数字服务适配

描述中小企业转型需求、数字服务能力披露、可解释的供需匹配，以及从尽调到退出的证据链。

平台要解决的核心问题：小型制造企业说的是**停机窗口短、预算有限、某道工序效率低**，而服务商常拿出一套功能齐全但未必适用的演示。因此平台只认真实资料：企业保存自己的产线基线、目标与约束，产品必须披露能力边界与实施前提，匹配逐项核对并说明理由，后续签约、部署、验收、指标变化、持续使用各自留痕，企业更换服务商时仍保有自己的证据。

## 资料结构

| 文件 | 内容 |
| --- | --- |
| `contracts/*.schema.json` | 七份 JSON Schema 契约（2020-12）：领域标识、行业目录、证据登记册、企业档案、产品披露、匹配、合作生命周期 |
| `fixtures/industries.json` | 行业、工序、指标目录（指标带单位与优劣方向） |
| `fixtures/evidence.json` | 证据登记册：实测读数、第三方报告、签署件、日志导出、案例、删除确认、导出清单 |
| `fixtures/enterprises.json` | 企业档案：产线、基线、目标指标、停机窗口/预算/网段等约束 |
| `fixtures/products.json` | 三家服务商的产品披露：能力声明（效果区间）、边界、前提、报价版本、可回访案例 |
| `fixtures/matches.json` | 三条匹配：推荐 / 拒绝 / 有条件，每项核对都注明字段出处 |
| `fixtures/engagements.json` | 一段成功合作（签约→部署→验收→读数→持续使用）与一段并行尽调失败退出 |

示例中的企业、服务商、案例与数值均为虚构，不含账号、凭据或真实主体信息。

## 平台强制的业务不变量

代码校验（`src/`）在 JSON Schema 的结构校验之外，额外保证：

1. **行业均值不能冒充企业现状。** 基线分 `enterprise_measured` 与 `industry_reference`，目标与匹配只接受实测基线；实测基线必须引用企业实测读数证据。
2. **演示功能不等于承诺。** 产品能力以披露为准，`limitations` 明确边界；能力声明给出效果区间并可关联案例。
3. **匹配给得出理由。** `industry / 痛点工序 / 停机窗口 / 预算 / 实施前提 / 目标指标 / 可验证案例` 七项由档案与披露**重新推导**，记录的结论与推导不一致即报错，推荐意见（proceed/conditional/reject）必须由核对结果得出。
4. **全功能旗舰版不因"功能多"而被推荐。** 痛点工序不被支持、停机 8h 超过 4h 窗口、报价超预算且需持续公网，任一硬约束不过即 reject；便宜但自认不解决痛点、案例不可回访的只能 conditional。
5. **多家可并行尽调。** 同一企业可同时存在多段 engagement；尽调沙箱与商业数据隔离是必填项，服务商不得可见企业商业数据。
6. **补贴占用可防重。** 同一企业同一政策同时只能有一笔未释放占用；失败退出必须释放。
7. **状态必须由记录支撑。** 声称已部署/已验收就必须有部署记录和通过的验收单；reject 的匹配不得签约；记录时间必须晚于基线测量且不允许倒挂。
8. **证据归企业且可携带。** `enterprise_owns_evidence` 与 `portable_on_switch` 必须为真；失败退出要有退出备忘、企业导出清单、服务商删除确认三件凭证。
9. **签约、部署、指标变化、阶段验收、持续使用分别可查**，指标变化相对企业实测基线计算（示例：检验工时 14.0→9.5 小时/批，-32.14%，落在披露的 25%–40% 区间）。

`src/matching.js` 的 `evaluateMatch` 可在不依赖任何已存匹配结论的情况下独立重算，便于以后接入真实数据时复算与审计。

## 本地校验

```bash
npm test
```

运行项目自带测试（Node 内置 test runner，零依赖）：7 项正例覆盖领域标识、完整链路与指标变化，11 项反例覆盖篡改核对结论、行业值冒充现状、重复补贴占用、证据不可携带、reject 后签约、时间倒挂等拦截场景。
